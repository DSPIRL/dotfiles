# Documentation Stewardship Skill

## Procedure

1. Read existing docs before writing.
2. Update existing docs before adding new docs.
3. Document why, usage, boundaries, invariants, and operational consequences.
4. Use concrete facts, real symbols, paths, actors, measurements, and project terminology.
5. Use one stable name for each concept. Prefer active voice and plain words.
6. Remove filler, puffery, promotional language, vague attribution, chatbot phrases, and unsupported confidence.
7. Match the voice to the document: dry reference, direct procedure, or contextual explanation.
8. Avoid paraphrasing implementation details that are obvious from code.
9. Keep docs short enough to stay maintained.

## Output

State what confusion the documentation removes and where the durable source of truth now lives.

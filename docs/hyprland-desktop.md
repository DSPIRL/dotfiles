# Hyprland desktop controls

The desktop uses the existing Quickshell configuration, Wallust accents, and neutral surfaces. It does not require another shell framework or a custom backend daemon.

## Controls and shortcuts

- `Super+A`: open/close controls on the focused monitor.
- Controls open in a top-right, screen-constrained 640 × 740 logical-pixel frame. Category icons retain text labels; narrow screens scroll the category strip. Quick is initial, and the last category is remembered until the shell restarts.
- **Quick**: Wi-Fi and Bluetooth radio toggles, network settings (`nmtui`), Bluetooth settings (`blueman-manager`), Night light, Keep awake, Quiet notifications, output mute/volume, laptop brightness (or the first adjustable external display), and Audio/Display shortcuts. Right-click, the Menu key, or Shift+F10 opens a radio tile's settings menu only when the tile is enabled; disabled tiles cannot open their menus. The menu item requires the corresponding tool and loaded, non-busy desktop settings. A request remains pending across page switches and panel closure; after five seconds without a matching state it reports “change not confirmed”, not necessarily failure, and stays disabled to prevent overlapping requests. A later matching state clears it; Wi-Fi backend loss or Bluetooth adapter replacement also resets the corresponding request. If it remains stuck, inspect the backend using its external tools, or restart the shell after checking the backend; restarting forgets the request, so first ensure the old operation is no longer in flight. Wi-Fi requires NetworkManager and an unblocked radio; Bluetooth requires an available, unblocked adapter. The installed Quickshell QML type metadata exposes writable properties and change signals but not setter implementation; whether a matching signal is an optimistic local update or backend confirmation is unverified. Its Networking backend property is marked constant, so NetworkManager service loss may not be observable as a backend change.
- Network status uses `nmcli` terse output; the inherited parser does not unescape connection names, so names containing escaped colons or backslashes can display with escape characters. Malformed means a nonempty row with fewer than three colon-separated fields, not semantic validation; malformed-only output displays as disconnected.
- **Music**: MPRIS artwork, title/artist/album, player selection, playback and capability-gated seeking. Missing players/artwork have fallbacks; only local file and HTTPS artwork URLs are loaded. Metadata is plain text. Position refreshes only while visible and playing, pausing during scrubbing. This is playback control, not a library manager; the Spotify bar remains unchanged.
- **Look & Feel**: shell glass, independent glass/control/window opacity, compositor-wide blur, light/dark theme, wallpaper, screen color picker and bar visibility.
- **Audio**: output/input devices, mute and volume. Only one device-selection submenu opens at once; Escape dismisses it before closing controls.
- **Display**: Night light, laptop/DDC brightness, monitor resolution and detection refresh.
- **System**: CPU/RAM/temperature (click for `btop`), software updates, diagnostics and maintenance. Low-effects mode, Lock and Session remain in the shared footer on every category.
- Bar status indicators: left-click volume for Audio, or Bluetooth/network for Quick. The clicked monitor's controls stay open and switch category even if already open. Right-click volume to mute/unmute, scroll over it to adjust volume, or right-click Bluetooth to open `blueman-manager` (or report its absence). Network has no right-click action. With no default audio sink, volume shows `--`; left-click still opens Audio, while mute and wheel do nothing. These work independently of the keyboard shortcuts.
- `Super+;`: toggle a dedicated Alacritty dropdown on `special:dropdown`. Hiding preserves its running shell, not its state across exit or session restart; exiting it makes the next toggle start a new one. The custom `Alt+Space` switcher excludes windows with initial class `dropdown-alacritty` (not other switchers); normal Alacritty remains listed. The floating window is 504 × 504 logical pixels, horizontally centered at y=53 on its monitor. Do not move it off `special:dropdown` or put other windows there: the toggle owns that workspace. This is one shared dropdown, not one per monitor; monitor selection and small/scaled display placement are not guaranteed. The vertical special-workspace animation affects all special workspaces; low-effects mode can disable animations. Concurrent presses are discarded while a toggle is in progress. IPC waits are limited to one second and startup to roughly five seconds; errors go to stderr. If startup times out, the launched process is not killed: check or close it before retrying to avoid a duplicate if it maps late.
- `Super+N`: open/close notification history.
- `Super+Shift+B`: show/hide the bar with a 200 ms, 12 px slide-and-fade (up to hide, down to show; no bounce). Low-effects mode makes the toggle instant. Controls remain accessible while it is hidden.
- `Super+Ctrl+R`: reload Hyprland.
- `Super+Shift+C`: toggle a centered, half-width floating window. Its height leaves room for both borders within the usable screen area; toggle again to restore its previous state.
- Active-window borders use the wallpaper-derived gradient without continuous rotation.
- `Super+Shift+L`: lock. Navigation, workspace movement, screenshots, and the exit shortcut are unchanged.
- Tab/Shift+Tab move focus; Space/Enter activate controls. Left/Right switch categories while a category has focus; Home/End select the first/last. Drag sliders or use arrow keys to adjust them. The mouse wheel scrolls the page—even over a focused slider—and never changes slider values. Escape dismisses a Quick radio settings menu or an audio device submenu, or backs out of session confirmation/actions before closing controls. Closing resets detail menus and confirmations, not the selected category. A category request also exits Session and clears any pending confirmation.

The former blur, opacity, performance, theme, diagnostics, and monitor-reapply shortcuts are replaced by the menu. Their scripts remain available for custom shortcuts.

The footer and bar power button open the session menu. Suspend, logout, reboot, and shutdown require confirmation. Missing dependencies are reported or disable the relevant control. Night light, Keep awake, and Quiet notifications save their selected state and restore it after shell restarts and logins. Quiet mode retains history and allows critical alerts; normal startup popups are suppressed until saved preferences are loaded. These are shared across monitors. This persists the notification preference, not notification history across process restarts.

## Typography (file-only)

Edit **`~/.config/quickshell/default/Typography.qml`** through chezmoi:

```bash
chezmoi edit --apply ~/.config/quickshell/default/Typography.qml
~/.config/hypr/scripts/quickshell-reload.sh
```

The managed source is `dot_config/quickshell/default/Typography.qml`. Its editable settings are grouped above the derived font roles:

- **Defaults**: `textFamily`, `iconFamily`, `normalWeight`, `emphasisWeight`, and icon weights.
- **Bar**: `barSize` changes every pill's text (default 14 logical pixels). Clock and workspace weights remain explicit; `barIconSize`/`barIconWeight` are independent. `barAudioIconSize` defaults to 20 for optical balance of Material volume glyphs with the other 14-pixel icons. Its fixed-width slot prevents state-dependent crowding; bar height and text sizing are unchanged.
- **Notifications**: title, body, metadata, and action sizes/weights. These apply to both popup and history-card content.
- **Notification center**: the panel title, empty state, header buttons, and decorative icon, independent of notification content.
- **Control center**: title, section headings, labels, emphasized buttons, hints, messages, metrics, and icons. `controlTileIconSize` controls dashboard/category and mute glyphs (default 20), with normal/emphasis weights; `controlIconSize` retains the small-icon font role. Neither changes bar icons. Audio and Quick mute targets are 40-pixel squares at the default typography, growing with text, and their adjacent headers match their height. Speaker/microphone glyphs use the same Material icon set.

Area families/weights inherit shared defaults until explicitly overridden. Use positive pixel sizes and named weights such as `Font.Normal`, `Font.Medium`, `Font.DemiBold`, and `Font.Bold`. Font families must be installed; unavailable faces/weights may fall back or be synthesized. Tray icons/application logos are images, not fonts.

Components bind complete font roles from one QML singleton; remaining state changes choose between those roles instead of adding local font overrides. Notification buttons explicitly select notification/center roles so control-center changes do not leak into them. Buttons/toggles and panel chrome grow with text metrics, but the bar's 36-pixel pills remain fixed: very large bar fonts can overflow, so check the live result.

Typography is trusted QML configuration, not a runtime preference database. It persists in the file and is not stored under `~/.local/state`. Wallpaper generation owns colors only and cannot reset these settings. There are no font controls in the UI. Apply/reload after editing, and check Quickshell logs for syntax or binding errors; no Hyprland reload is needed.

## Quickshell design-system foundation

Work in `dot_config/quickshell/default/`, not the generated target. `Tokens.qml` owns hand-maintained, shared non-color geometry and motion roles; add a role only for demonstrated semantic reuse, not merely equal numbers. `Typography.qml` owns font roles. Wallpaper-generated palette data belongs in `wallust/Colors.qml.tmpl` (and the fallback palette), not in layout tokens. Keep page-specific layout and geometry-derived values local.

Use `components/GlassSurface.qml` for shared glass material and `components/ActionButton.qml` for shell-wide actions. `components/control/ControlSlider.qml` and `ControlToggle.qml` remain control-center components; there is no shared card, heading, or row primitive. Keep distinct card treatments local rather than wrapping them in a speculative shared component. See the token and primitive contracts in `PLAN.md` for the evidence and boundaries.

Interactive components must account for normal, hover, pressed, keyboard focus, selected/checked and disabled states where applicable, with accessible names/roles and keyboard and pointer operation. Preserve visible focus and selection at control-opacity extremes; at zero opacity the hover fill is intentionally invisible. Guard nonessential motion and expensive effects in low-effects mode and preserve saved preferences. Use existing Qt control semantics rather than inventing a pressed fill.

### Composition example

Notification history demonstrates the shared foundation without importing control-center components. `components/notifications/NotificationPanel.qml` places `NotificationCard` inside `GlassSurface`, using `Tokens.panelRadius` and the supplied Wallust palette. The card's action delegate uses `ActionButton`, `Tokens.notificationActionMinHeight`, and `Typography.notificationActionFont`; `ActionButton` supplies keyboard and pointer behavior, focus/hover styling, accessible text, and a tokenized color-transition duration. Its color animation is disabled in low-effects mode.

The card itself remains bespoke: its rectangle, hover and urgency border, content layout, and action list are local. Each action invokes the notification's action and dismisses the notification; the panel owns visibility, initial focus, Escape and hidden-bar positioning. The card is not itself a `GlassSurface`, and no shared card, slider or toggle is needed for this composition. Offscreen button and typography tests exercise shared pieces with doubles, not notification delivery or action invocation; low-effects transition reversal and live panel behavior still need their separate checks.

## Rofi appearance

The shared `dot_config/rofi/config.rasi` enables `hover-select: true`, clears `me-select-entry`, and sets `me-accept-entry: "MousePrimary"`. All launcher styles inherit hover selection and single left-click activation for list/grid items; keyboard behavior is unchanged. Search and calculator modes hide results and still use Enter. Deploy source edits with chezmoi, then close and reopen Rofi.

The existing application, run, window, search, calculator, clipboard, emoji, and image-grid launchers share a Quickshell-like glass theme: a translucent gradient, 26-pixel outer corners, quiet card selections, and wallpaper accents. Hyprland supplies backdrop blur; there is no screenshot/refraction shader. Search-only modes keep the same padded input surface as the main launcher. All eight launcher configs share the same top-center anchor and 18% vertical offset in `rofi/themes/templates/rounded-template-wallust.rasi`; different window heights/widths do not move that anchor. Change placement there, not in individual mode configs.

The application launcher alone (`config-apps.rasi`) uses 42-pixel icons, name-only rows, separators, and six visible results (four on short displays). Generic names, keywords and desktop comments are searchable: `drun-match-fields` includes `name,generic,exec,categories,keywords,comment`, while `drun-display-format` shows only `{name}`. Other modes retain their own compact/grid layouts.

Edit `~/.config/rofi/appearance.rasi` through chezmoi for Rofi-only fonts and corner radii. The default text is `Noto Sans 14px` (explicit Pango pixels, not 14 points); emoji grids use a larger emoji font. Layout lives in `rofi/themes/templates/rounded-template-wallust.rasi`, with grid-specific overrides. Close and reopen Rofi after applying edits; neither Quickshell nor Hyprland needs a reload.

Rofi does not read `Typography.qml` or Quickshell's glass/control opacity percentages. Its material has independent defaults. Backdrop blur is already shared through the compositor. Low-effects changes regenerate an opaque Rofi palette for the next launch, without changing GTK/KDE themes; if regeneration fails, the preference rolls back.

`toggle-breeze-theme.sh refresh-shell` renders the current light/dark and low-effects state into `~/.config/rofi/wallust/colors-rofi.rasi`, preserving a validated opaque accent token. Wallpaper refresh calls the same renderer after Wallust. Generation is locked and atomic, so parallel refreshes cannot expose partial Rasi. Edit the source templates/renderer rather than this generated file; the renderer never edits `appearance.rasi`.

`bash tests/rofi-theme.sh` checks accent migration/preservation, light/dark materials, low-effects and rollback, concurrent generation, and every launcher config using Rofi's resolved-theme output when available. Native visual checks use synthetic text, emoji, and image entries—not clipboard contents—and cancel without selecting a launcher action.

### Effects benchmark

Run `~/.config/hypr/scripts/benchmark-effects.sh` to compare the saved full-effects configuration with low-effects mode. It measures stationary and workspace-transition compositor CPU/GPU use, a foreground SHA-256 task, and battery draw when the battery is discharging. Four paired rounds alternate mode order. On normal completion the script verifies restoration of the original workspace and low-effects setting; its exit trap attempts best-effort restoration after an ordinary interruption, but forced termination cannot guarantee it. A default battery run takes about six to seven minutes and is shorter when battery measurement is unavailable; `--quick` performs a lower-confidence check. Use `--battery-seconds 60` or longer when small power differences matter, or `--no-battery` to skip battery measurements.

Leave the desktop untouched, keep brightness fixed, close unrelated busy applications, and unplug external power for comparable battery results. The script holds an idle inhibitor, so automatic locking and display blanking remain suppressed while it runs. Battery draw is measured only during stationary segments; transition and foreground-task power are intentionally excluded. Results, metadata, Hyperfine data, and a printable report are saved under `${XDG_STATE_HOME:-~/.local/state}/hypr/benchmarks/<timestamp>/`.

Runtime preferences live in `${XDG_STATE_HOME:-~/.local/state}/hypr/effects/`. The first invocation imports the old live Lua flags; managed Lua files subsequently supply defaults only. Applying chezmoi no longer resets these preferences. Effect toggles apply only the relevant compositor settings and existing opacity/layer-blur rules through `hyprctl repl`; they do not reload the config, reapply monitors, or reset centered-workspace/window state. A failed update restores the previous preference and attempts to reapply it. Shell glass, glass/control opacity, Keep awake, and Quiet notifications are shell-only: changing them saves preferences for Quickshell to observe, without calling the compositor or changing window rules.

The bar keeps its layer surface mapped and animates only its contents, avoiding a second compositor transition or changes to notification/control-center animations. Hidden and transitioning contents accept no pointer input. Screen space is released after hiding and reserved again when showing; rapid toggles reverse from the current animation position.

Adjust `pillMargin` in `dot_config/quickshell/default/components/BarSurface.qml` to change the space around the bar pills. It defaults to 4 logical pixels on every side; 36-pixel pills therefore reserve a 44-pixel bar area. Input regions and clock placement follow the same setting. Hyprland's own window gaps still contribute to the distance below the bar and are unchanged.

The bar uses three floating glass sections: workspaces (plus Spotify on wide screens), a centered clock/date, and tray/essential status indicators. The clock hides when there is insufficient space; glass gaps pass pointer input through to the desktop. By default, all bar-pill text—workspaces, clock, media, and status percentages—uses Noto Sans at 14 logical pixels; Nerd Font glyphs are separate icon-only labels, so numbers do not inherit the icon font. The bar, control center, notification center, and notification popups share a clear light material and a smoke-tinted dark material, using Hyprland backdrop blur—not optical refraction or screen capture. Low-alpha fills, translucent cards, and fading highlights along the top and bottom edges suggest curved glass without a heavy white or dark wash. Shared `GlassSurface.qml` is shadowless: tight layer/popup bounds can crop shadow paint and interact with the compositor's blur-alpha threshold. It retains the fill, border, edge highlights and hover overlay. Glass styling does not change compositor-wide blur strength or alpha thresholds; the explicit Hyprland blur slider controls strength.

### Control-center separate-shadow pilot

**The shared-shadow extension is deployed with user authorization:** bar, controls, notification history/toast and styled tray. The control-only pilot is historical. Quickshell hot-reloaded successfully and `hyprctl configerrors` was empty; live bar/history geometry and a cropped capture show soft shadows. Live tray/toast, actual pointer delivery and scales remain user acceptance checks, not established by deployment. `GlassSurface.qml` stays shadowless. Each supported owner creates its own separate, hollow, unblurred shadow window. The former shared `shadowEnabled` path and faint alpha caps are superseded. Glass blur thresholds remain unchanged.

`components/SurfaceShadow.qml` is paint-only: blur 12/offset (0,3), dark/light source alpha .6/.5, then an inverted rounded union cutout. Callers supply `panelRects` and a common radius. All bar pills share one source layer, one union-mask layer and one `MultiEffect`; a neighboring pill's shadow cannot paint inside another pill. The old control-local renderer is removed, not wrapped. Low-effects and effective zero glass opacity suppress shadows without changing preferences; opaque Shell-glass-off surfaces still cast shadows. Isolated OpenGL top/side/bottom alpha remains 30/58/91 (dark) and 25/48/76 (light), out of 255—not a cross-renderer pixel guarantee.

Current deployed owners and runtime namespaces (not Lua rule names):

| Owner under `components/` | Shadow namespace | Glass/menu path |
|---|---|---|
| `BarSurface.qml` | `quickshell-bar-shadow` | `quickshell` bar layer |
| `control/ControlPanel.qml` | `quickshell-control-shadow` | `quickshell` control layer |
| `notifications/NotificationPanel.qml` | `quickshell-notification-shadow` | `quickshell` history layer |
| `notifications/NotificationToast.qml` | `quickshell-toast-shadow` | `quickshell` toast layer |
| `bar/SystemTraySection.qml` | `quickshell-tray-shadow` | styled popup attached to the bar; native fallback unchanged |

All five shadows are Top layers with empty input regions, no keyboard focus and `ExclusionMode.Ignore`. Overlay shadow buffers request their owner's implicit dimensions, avoiding a transient 1×1 native owner size at first mapping. Tray placement/lifecycle has its own first-frame gate, described under verification below.

`BarSurface.qml` contains only the existing native geometry/reveal/input policy and the new shadow; `BarWindow.qml` still owns services, coordination and the real pills. This narrow seam lets native tests supply plain rectangles without initializing services. The bar's glass buffer/reservation stays 44px, with the same rounded island input regions. Only its shadow buffer grows by 15px below the bar; opacity and −12px reveal translation follow `barReveal`, and hidden clocks leave no shadow/cutout. The existing 4px pill top inset is smaller than the 9px upper shadow envelope: the physical screen edge necessarily crops the top shadow (and outer side edges). A larger buffer cannot paint outside the monitor; moving the bar to avoid this would change its geometry and is not done.

Notification center/toast buffers gain transparent extents 12/12/9/15, while glass stays at the original screen position, width (up to 440px), content-local coordinates and height limits. History's 520px/viewport cap excludes padding; toast text limits, timers, suppression and focus policy are unchanged. Rounded glass-only input regions exclude all padding.

Control-center windows retain padding 12/12/9/15 (664 × 764 at full size). Visible glass remains 640 × 740, constrained as before, right 12/top bar-height + 12 (hidden bar: top 12), with unchanged local layout and rounded glass-only input mask.

**Required compositor rule and version contract:** `dot_config/hypr/config/windows_and_workspaces.lua` defines `control-center-shadow` plus `quickshell-{bar,notification,toast,tray}-shadow`, each matching only its exact shadow namespace, with `order = 1`, `blur = false`, `blur_popups = false`, and `no_anim = true`. Keep all five namespaces out of `effects.apply()`'s blur namespace list, which remains exactly `quickshell`, `rofi`, `notifications`; do not broaden it to a `quickshell.*` prefix match. The ordinary glass keeps `ignore_alpha 0.1`; separate shadow alpha is not capped by that glass threshold. Hyprland **0.56.2** sorts same-layer surfaces by descending order and paints forwards ([v0.56.2 `Renderer.cpp`](https://github.com/hyprwm/Hyprland/blob/v0.56.2/src/render/Renderer.cpp), `arrangeLayersForMonitor` and `renderAllClientsForWorkspace`): order-1 Top shadow paints **behind order-0 Top glass**, with both above applications. This does not rely on QML z, declaration or map order. FullMatch namespace matching keeps the existing `quickshell` blur/alpha rules off this surface. Shadow-only `no_anim` prevents detached fadeout snapshots from bypassing mapped-layer order; glass transitions remain unchanged. Layer popups paint after Top/Overlay surfaces, so the tray popup paints above its shadow; order 1 also keeps that shadow behind the bar.

This ordering contract was checked against versioned 0.56.2 and 0.57.0 source and both executable rule parsers. The session ran 0.56.2 during deployment; installed 0.57.0 preserves the same sort/paint, FullMatch and no-animation contracts. A disposable 0.57.0 compositor failed before fixtures, so its pixel output is not verified. Identify the **running** compositor with `hyprctl version`, not just the installed binary, and revalidate on upgrades.

**Cost and limits:** each active shadow owner adds one native surface, two offscreen texture layers and one masking/compositing pass using existing Qt effects. The bar uses **one full-width pipeline per monitor, not one per pill**: at default geometry its canvas is monitor width × 59 logical pixels (44 + 15). Control, history and toast each use a separate padded panel-sized pipeline when active; each styled tray delegate owns another surface, mapped only for its active popup. Native-surface count and texture cost therefore grow with active owners and monitors, not just component reuse. GPU time/memory and scaling costs have not been benchmarked. No runtime dependency or shader toolchain is added.

The paired windows do not guarantee frame-atomic updates, and instant shadow lifecycle does not promise matching custom slide/popin layer animations. Physical screen edges crop the bar/tray envelope. Component captures and KWin geometry/input fixtures do not prove Hyprland pixel stacking/blur, wallpaper contrast, physical scaling or live glass transitions; the tray's delivered input checks do not establish padding click-through for the other owners. Live bar/history evidence below is limited to the observed configuration. Existing bar low-effects and rapid-toggle/focus limitations remain open; sharing the renderer does not fix them.

### Glass and window opacity

Shell glass is enabled by default and independently controls transparency of the bar, control center, and notifications. Configured transparency enables the Hyprland window-opacity slider for normal application windows. Its uniform percentage overrides the existing per-app opacity rules; `100%` is opaque and fullscreen windows always remain opaque. Turning the feature off or enabling low-effects mode forces normal windows opaque too, without erasing the saved percentage. It does not affect shell glass or an application's own background-alpha setting. Backdrop blur controls frosting independently: with blur off, glass remains transparent but unfrosted.

**Super+A → Look & Feel** replaces the old Desktop/Appearance disclosure. The category itself keeps niche settings off Quick; Low-effects stays in the persistent footer. Settings remain grouped by target:

- **Shell surfaces**: Shell glass, Glass opacity, and Control opacity. These affect shell backgrounds and control-center fills, not application windows.
- **Application windows**: Configured transparency and Hyprland window opacity.
- **Backdrop blur**: the shared compositor blur switch and strength, affecting blur-enabled windows and shell surfaces independently of opacity.
- **Theme & wallpaper**: two flat rows, without an enclosing card. Theme choices show an accent pill/checkmark only for the selected option; Wallpaper is a separate hoverable action row. Keyboard-focus outlines remain visible, and narrow/larger-font layouts wrap the selector rather than nesting another card.

The four sliders remain independent:

- **Glass opacity** (`0–100%`, default `40%`): shared backgrounds of the bar, control center, notification center, and notification popups. The old `control-center-opacity` value is imported once unless a global glass value already exists.
- **Control opacity** (`0–100%`, default `100%`): only control-center buttons/cards, including selected/hovered/disabled fills. Text and icons do not fade. It remains independent of Glass opacity and Shell glass; notification controls are unaffected.
- **Hyprland window opacity** (`0–100%`, default `100%`): uniform compositor opacity of normal windows when Configured transparency is enabled. It deliberately supersedes per-app opacity rules so the slider has consistent results even for applications with `override` rules. Fullscreen windows stay opaque. Changing only `decoration.active_opacity` was rejected because those per-app overrides would bypass the slider.
- **Hyprland blur size** (`1–20`, default `3`): compositor-wide blur size when Backdrop blur is enabled. Blur passes are left unchanged; stronger blur costs more GPU time and affects only surfaces with blur enabled.

Shell fill previews update immediately. One serialized, latest-value queue throttles numeric writes/compositor updates at a 60 ms interval (waiting for any current command), so long drags continue to preview rather than waiting for release and trailing edits are not lost. Values persist across shell restarts; unrelated monitor/layout/window rules are not reapplied. Named opacity rules merge in place instead of accumulating one rule per edit.

Low-effects mode overrides blur, configured transparency, shell glass, animations, and shadows without erasing their saved preferences. The menu shows effective state and disables overridden switches. Turning off Shell glass makes glass backgrounds opaque; control opacity remains independent. Low-effects mode forces both glass backgrounds and control fills opaque. Shell animations also stop in low-effects mode.

System statistics refresh only while System is visible. Software updates use `checkupdates` on the first System visit and every 15 minutes while visible, with a manual Refresh button. System remains instantiated after first use so in-flight checks can finish and results are cached for 15 minutes across page switches/reopens; hidden timers pause. A failed check is unavailable, not zero updates. Updating opens the existing terminal with `paru -Syu` (or `sudo pacman -Syu` when `paru` is absent). The color picker closes controls before sampling, so it does not sample the panel itself.

Theme state remains in `${XDG_STATE_HOME:-~/.local/state}/hypr/breeze-theme`. The existing theme script updates application themes and Rofi surfaces; Quickshell observes the same preference. `wallust-refresh` applies Hyprland border/group colors directly, reapplies Rofi's selected light/dark surface after generating wallpaper colors, and restarts an already-running Quickshell to load its new palette. Hyprland deliberately loads its generated Lua palette with `dofile`, not `require`, to keep wallpaper updates out of its config watcher. Running `wallust run` directly updates the file but does not apply Hyprland colors until the next refresh or config reload. Update both the Quickshell fallback palette and its Wallust template when changing shared style tokens.

When first deploying these changes, load the new Lua modules at the next login or with one explicit config reload when it is safe to reset runtime layout state. Subsequent appearance toggles and wallpaper refreshes need no full reload. **Reload Hyprland**, `Super+Ctrl+R`, and edits to watched config modules still perform a full reload and can reset runtime layouts; **Reapply monitor configuration** also intentionally changes display geometry.

## Night light and saved session choices

`night-light`, `keep-awake`, and `quiet-notifications` use the same atomic, locked preference store as the appearance controls. New installs default them off; first use imports an already-running night-light daemon. Existing `hyprsunset.sh enable|disable|toggle` commands also save the choice. Its `status` operation reports the running daemon; `desktop-settings.sh night-light status` reports the saved choice. The status JSON exposes both `nightLight` (actual) and `nightLightWanted` (saved).

Quickshell applies the saved night-light choice once at startup, launching `hyprsunset -t 4000` only if no same-UID daemon is found. An existing daemon is not adjusted, so the UI's 4000 K subtitle does not verify its actual temperature. Detection and stopping are same-UID rather than session-specific; disabling can affect another session. Adjustable temperature is not implemented and is blocked pending a safe ownership and migration policy (see `PLAN.md`). Runtime restoration and manual toggles share a separate lock, and the daemon inherits neither lock nor command stdio. This avoids duplicate daemons and settings commands hanging behind a long-lived child. Failed manual changes roll back the saved choice; failed startup restoration leaves the choice saved and reports an error so the next restart can retry.

## Idle locking and keep-awake

`hypridle` starts with Hyprland using `~/.config/hypr/hypridle.conf`:

- Lock after five idle minutes using `hyprlock`.
- Blank displays after five and a half idle minutes; restore them on activity.
- Request locking before sleep and delay sleep until the Wayland session is locked (`inhibit_sleep = 3`).

Keep-awake holds a systemd **idle-only** inhibitor. It suppresses automatic idle actions, including while the bar is hidden. It does not inhibit sleep, manual locking, or lock-before-sleep. The inhibitor releases when disabled or Quickshell exits; a new shell reacquires it when the saved choice is on. It can be acquired before hypridle starts, avoiding a login-order race. Keep awake suppresses automatic idle locking/display blanking until switched off, including after a reboot. A runtime inhibitor failure does not erase the saved choice: the control reports it unavailable and can be toggled off/on to retry. The Suspend action also requires a running hypridle and installed hyprlock.

Principles are of the utmost importance. You do not break Principles. If you believe a Principle should be broken, confirm with a human before doing so.

# Important Rules to Follow
## Comments
- Only add comments to code when explicitly requested by a human. If you believe a comment is of utmost importance, explain why and ask for permission first.

## Documentation
- Do not write prose that justifies, defends, or explains away your own decisions (in markdown, comments, commit messages, or PR descriptions). If a decision needs justification, raise it with a human in conversation instead.
- Do not create new markdown files (summaries, notes, reports, plans) unless a human or a human-invoked skill/command asks for one.
- Editing existing docs is fine when it is the task, or when a skill the human invoked directs it. README updates for usage/setup documentation are always fine.
- When the task is creating or refining a spec, you may create and edit spec files. Specs describe what to build and how it should behave; they are not a place to justify implementation decisions.
- Otherwise, propose the markdown change and wait for approval.
